# SatQuery AI — frontend

The console a judge actually touches. Built against the frozen contract in
`contracts/openapi.yaml`, running entirely on MSW mocks until the backend
exists.

See [`FRONTEND_PLAN.md`](FRONTEND_PLAN.md) for the work package,
[`../PRODUCT.md`](../PRODUCT.md) for product truth, and
[`../DESIGN.md`](../DESIGN.md) for the visual system.

---

## Run it

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

Opens on `http://localhost:5173`. Mocks are on by default — no backend needed.

| Command | Does |
|---|---|
| `npm run dev` | Dev server with MSW mocks |
| `npm run build` | Typecheck + production build |
| `npm run typecheck` | `tsc -b --noEmit` |
| `npm run test` | Vitest — fixture schema validation + pair rules |
| `node scripts/shoot.mjs <url> <outDir>` | Screenshot every screen at desktop and mobile |
| `node scripts/calibrate-masks.mjs` | Re-derive mask thresholds from the fixture areas |

### Environment

| Variable | Default | Meaning |
|---|---|---|
| `VITE_API_BASE` | `http://localhost:8000/api/v1` | Backend base URL |
| `VITE_USE_MOCKS` | `1` | `0` points at the live API. This is the whole of "going live". |
| `VITE_MOCK_SPEED` | `1` | Scales mock SSE replay. `2` = twice as fast. |
| `VITE_MAX_UPLOAD_BYTES` | `4294967296` | Client-side upload cap pre-check |
| `VITE_ENABLE_BASEMAP` | `0` | `1` enables an OSM raster basemap. **Development only** — it makes external requests, and the venue is offline. |
| `VITE_API_KEY` | — | Reserved. Sent as `X-Api-Key` when set. |

## What is built (Phase 1 — UI)

All seven screens, fully interactive against mocks.

| Screen | Route | State |
|---|---|---|
| S1 Sessions | `/` | Pre-warmed records, two-SLA gauge, receiving bay |
| S2 Receiving | `/upload` | Multi-file drop, byte-level progress, role designation, client-side pair validation |
| S3 Preparation | `/prepare/:bundleId` | P1–P4 stage rows over the job SSE, skipped stages shown greyed, live compatibility |
| S4 Workspace | `/workspace/:bundleId` | Layers + MapLibre + chat/trace, A/B swipe, tile grid, non-geo fallback viewer |
| S5 Trace | `/workspace/:bundleId` → Trace tab | The graded block, parameters against manifest, steps accordion |
| S6 Report | `/workspace/:bundleId/report/:queryId` | Document preview, section selection, PDF job, print fallback |
| S7 System | `/system` | Health, client config, calibration, disagreement causes, tool manifests |

**The three graded behaviours are live:** refusals render as advisory cards
with a working remedy across all five categories; confidence is badged
differently for `heuristic` and `calibrated`; the optical/SAR disagreement
panel names the cause, the trusted modality and the IoU.

## What is Phase 2 (needs backend or logic work)

- **Real imagery.** Every raster is generated by `mocks/synthetic.ts` and
  labelled synthetic. Swaps to `GET /scenes/{id}/tiles/...` with no UI change.
- **PDF report rendering.** The frontend starts the job and downloads the file;
  the backend produces it. The print stylesheet is the shipped fallback.
- **Calibration display.** The reliability diagram is drawn with its diagonal
  and nothing plotted, because no calibrator is fitted. It fills in when the
  backend reports one.
- **Chunked upload.** The transport is isolated in `api/client.ts:uploadScene`;
  if the size cap forces `POST /scenes/init` + `PUT .../parts/{n}`, only that
  function changes.
- **Playwright demo-flow E2E.** `scripts/shoot.mjs` already drives the full
  path (ask → stream → trace → refusal) and is the skeleton for it.
- **Grounding boxes.** `bbox_px` rendering exists in the non-geo viewer; no
  fixture exercises it yet.

## Layout

```
frontend/
├── contracts/         frozen API surface (openapi.yaml, types.ts)
├── mocks/
│   ├── handlers.ts    every §4 endpoint
│   ├── sse.ts         scripted event replay with Last-Event-ID resumption
│   ├── synthetic.ts   the seeded world every raster is drawn from
│   └── fixtures/      the plan's fixtures, verbatim
├── scripts/           screenshots, mask calibration
├── tests/             Ajv fixture validation, pair rules
└── src/
    ├── api/           one file per resource + the SSE hook
    ├── components/    panel primitives, authored icons, SLA gauge
    ├── features/      landing · upload · prepare · workspace · chat · evidence · trace · report · system
    ├── map/           MapLibre wrapper + the non-georeferenced viewer
    ├── store/         zustand: workspace layers, live runs
    └── styles/        theme.css — the whole visual system
```

## Bundle budget

Target is < 500 KB gzipped JS excluding MapLibre. Current:

| Chunk | gzipped | Notes |
|---|---|---|
| `index` | ~89 KB | The demo path |
| `maplibre` | ~225 KB | Excluded from the budget by the plan |
| `charts` | ~155 KB | Lazy — `/system` only |
| `browser` (MSW) | ~109 KB | Lazy — never fetched when `VITE_USE_MOCKS=0` |

Fonts are self-hosted woff2, subset by Fontsource. No CDN, no telemetry.

## Integration

The day the backend has `/meta/health` and `/meta/tools`, set
`VITE_USE_MOCKS=0` and point `VITE_API_BASE` at it. Keep both paths working —
the mock path is the venue's insurance policy.

If the backend changes `configs/trace_schema.json` without a version bump,
`npm test` fails first. That is the alarm, and it is deliberate.
